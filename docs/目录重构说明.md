# 目录重构说明（给其它会话的 agent 看）

> 版本：v1.0.5.0（2026-11-04）
> 一句话：**按能力分目录，共用部分抽到 core/；老路径保留兼容层，旧命令仍能跑。**

## 1. 为什么要动

工程同时长着两套能力（UniMate 抽卡、Motion2MixamoRig 动补），脚本和工具却平铺在
`scripts/` 和 `tools/` 里，五类东西混在一起：抽卡、库接入、体检质检、交付、底座。
再接一个能力就分不清"哪条命令属于谁"。

## 2. 新结构

`````````
AIGenAnimPrj/
├── core/                    跨来源共用（不依赖任何产线）
│   ├── env.sh               读 config.env、导出路径变量
│   ├── pipeline_config.py   同一套配置的 Python 侧
│   ├── action_meta.py       动作契约 action.json
│   └── action_index.py      动作索引 + 体检
├── pipelines/
│   └── unimate/             UniMate 抽卡与库片段接入
│       ├── scripts/         unimate-*.sh（入口）
│       ├── tools/           实现（make_loop / flatten_root / gait_report …）
│       └── README.md
├── Motion2MixamoRig/        动补重定向（保持原位，未改动）
├── scripts/  tools/         ★ 兼容层：只转发 + 打印弃用提示
├── docs/                    规范与记录
├── outputs/                 rig / samples / actions（不入库）
└── setup.sh  VERSION  CHANGELOG.md  AGENTS.md  README.md
`````````

## 4. 对调用方的影响

> **v1.0.5.6 起兼容层已回收**：`scripts/` 与 `tools/` 两个目录已从仓库移除（备份在 `.trash/`）。
> 下表是过渡期的历史记录，旧命令现在会直接报"没有那个文件"，请改用新路径。

| 你原来写 | 现在 | 结果 |
|---|---|---|
| `bash scripts/unimate-loop.sh ...` | 仍可用 | 兼容层转发，并打印一行弃用提示 |
| `bash pipelines/unimate/scripts/unimate-loop.sh ...` | **推荐** | 直接跑，无提示 |
| `python tools/action_index.py` | 仍可用 | 兼容层转发 |
| `python core/action_index.py` | **推荐** | 直接跑 |
| `source scripts/_env.sh` | 仍可用 | 转发到 `core/env.sh` |
| `source core/env.sh` | **推荐** | |
| `$TOOLS/xxx.py` | 仍可用 | `env.sh` 里 `TOOLS` 已指向 `UM_TOOLS` |

**兼容层已在 v1.0.5.6 删除。** 如果你的脚本里还写着 `scripts/xxx.sh` 或 `tools/xxx.py`，
按上面的映射表改到 `pipelines/unimate/` 或 `core/`。

## 5. 脚本里新增的变量（`core/env.sh` 导出）

| 变量 | 指向 |
|---|---|
| `PIPELINE_HOME` | 仓库根 |
| `CORE_HOME` | `core/` |
| `UM_PIPELINE` | `pipelines/unimate/` |
| `UM_SCRIPTS` | `pipelines/unimate/scripts/` |
| `UM_TOOLS` | `pipelines/unimate/tools/` |
| `UNIMATE_HOME` | **外部上游仓库**（只读，不在本工程内） |
| `ACTIONS_HOME` / `SAMPLES_HOME` / `RIGS_HOME` | `outputs/actions` / `outputs/samples` / `outputs/rig` |

`PYTHONPATH` 现在包含 `core` 与 `UM_TOOLS`，所以
`python core/action_index.py` 不需要手动加 `PYTHONPATH`。

## 6. ⚠️ 命名坑（重要）

工作区里有**两个**"UniMate"，含义完全不同：

| 名字 | 路径 | 性质 |
|---|---|---|
| `$UNIMATE_HOME` | `H:/aiworks/motionPrj/UniMate/` | **外部上游仓库**，只读，禁止改 |
| `pipelines/unimate/` | `AIGenAnimPrj/pipelines/unimate/` | **我们的产线封装**，可以改 |

所以内部目录用的是**小写** `unimate`，并且永远带 `pipelines/` 前缀。
看到 `UNIMATE_HOME` 就想到"上游"，看到 `UM_*` 就想到"我们自己的"。

## 7. 顺带修掉的两个老 bug
