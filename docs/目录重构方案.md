# 目录重构方案（按能力分目录）

## 现状的问题

`scripts/` 和 `tools/` 现在是**平铺**的，一个目录里同时装着：

| 能力 | 现有文件 |
|---|---|
| UniMate 抽卡 | `unimate-pipeline.sh`、`unimate-sample.sh`、`unimate-animate.sh`、`unimate-loop.sh`、`make_loop.py`、`loop_close.py`、`flatten_root.py`、`add_root_spin.py`… |
| 动作库接入 | `unimate-import-clip.sh`、`unimate-import-batch.sh`、`remap_motion_joints.py`、`simplify_rig.py` |
| 体检与质检 | `inspect_rig.py`、`gait_report.py`、`verify_anim.py`、`roll_check.py`、`caption_stats.py`、`cycle_candidates.py` |
| 交付 | `bundle_unity.py`、`action_meta.py`、`action_index.py` |
| 跨来源底座 | `_env.sh`、`pipeline_config.py` |

再接 Motion2MixamoRig 就会更挤，而且"哪条命令属于哪个能力"要靠文件名猜。

## 建议布局

`````````

│   ├── env.sh               配置与路径解析（现 core/env.sh）
│   ├── pipeline_config.py
│   └── action_meta.py       动作契约
│   └── action_index.py      总索引

│   ├── unimate/             抽卡产线
│   │   ├── scripts/         pipeline/sample/animate/loop
│   │   ├── tools/           make_loop / loop_close / flatten_root / add_root_spin …
│   │   └── README.md        这条产线怎么用
│   ├── library/             动作库接入（import-clip / batch / remap）
│   └── m2mr/                动捕重定向（Motion2MixamoRig）
├── docs/
└── outputs/actions/         ★ 各产线的交付物都落这里，契约一致
`````````

## ⚠️ 一个命名上的坑（重要）

**不建议**把内部目录叫 `AIGenAnimPrj/UniMate/`，因为工作区里已经有一个外部仓库
`H:/aiworks/motionPrj/UniMate/`，那是 `UNIMATE_HOME` 指向的上游依赖（只读、不改）。

两个 "`UniMate`" 同时存在，会让每次排查路径都要先问"这是哪个 UniMate"：

- `$UNIMATE_HOME` → 上游模型仓库（只读）
- `$PIPELINE_HOME/UniMate/` → 我们自己的产线封装（可改）

脚本里这两者只差几个字符，写错就是"改到上游"或"找不到脚本"。

所以建议：
1. 内部目录用小写 `pipelines/unimate/`（或 `pipelines/gacha/`），并在 README 第一行写明
   "这是产线封装，不是上游模型仓库"；
2. `core/env.sh` 里把两个变量分开且带注释：`UNIMATE_HOME`（上游）与
   `UM_PIPELINE`（我们的封装）。

## 迁移步骤（每步都能单独回滚）

| 步 | 做什么 | 验证 |
|---|---|---|
| 1 | 建 `core/`、`pipelines/{unimate,library,m2mr}/`，`git mv` 搬文件 | `bash -n` 全脚本 + `py_compile` 全工具 |
| 2 | 改 `core/env.sh`：新增 `UM_PIPELINE`、`UM_TOOLS`、`M2MR_PIPELINE`；老路径 `scripts/`、`tools/` 留**薄封装**（转发 + 打印弃用提示） | 老命令照常能跑（回归一次 X Bot 走跑 + Dog 循环 + 一个库动作） |
| 3 | 更新 README / AGENTS / 操作手册里的路径；删薄封装 | 索引里 19 条动作仍可访问 |

## 工作量估计

- 第 1 步：机械搬移 + 改 ~15 处内部引用（`grep -rn 'TOOLS/\|scripts/'`），约 1 小时含回归。
- 第 2 步：薄封装 ~40 行；回归跑 3 条命令。
- 第 3 步：改文档里的路径，约 20 分钟。

## 我的建议

先做第 1、2 步（搬 + 兼容层），验证一轮再删旧路径。
**不要一次搬完还顺手改逻辑**——目录重构和功能改动混在一起，出问题分不清是谁的锅。
