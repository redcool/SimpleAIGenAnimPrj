# 动作产线规范

> 一句话：**UniMate 生成 + 动作库接入 = 覆盖整个项目的动作需求**，
> 两条产线在 `AIGenAnimPrj` 汇总成同一种产物。

## 1. 三个来源，一个出口

`````````
                ┌──────────────────────────────┐
动作需求 ──────> │  先查能不能生成               │
                │  python pipelines/unimate/tools/caption_stats  │
                └───────────┬──────────────────┘
                            │
         占比 ≥1% ──────────┴────────── 查不到 / <1%
              │                              │
      ┌───────▼────────┐           ┌─────────▼──────────┐
      │ 产线 A：模型生成 │           │ 产线 B：动作库接入   │
      │ unimate-pipeline │           │ unimate-import-clip │
      │ unimate-loop     │           │                    │
      └───────┬────────┘           └─────────┬──────────┘
              │                              │
              └──────────┬───────────────────┘
                         ▼
              outputs/.../action.json  （统一契约）
                         ▼
                 Unity / 引擎
`````````

**混合场景**（产线 C）：库里没有、但机械可补的（整圈翻转、根位移），
用 `add_root_spin.py` / `flatten_root.py` 加工模型产物 —— 只适合刚体或基础动作已够足的情况。

## 1.1 来源优先级（硬规则）

| 顺序 | 来源 | 用在哪 | action.json 标记 |
|---|---|---|---|
| 1 | **模型生成** | 分布内动作；能出随机变体 | `source: model` |
| 2 | **动作库** | 模型做不出/做不好 | `source: library` |
| 3 | 程序补 | 刚体、根位移 | `source: hybrid` |

**先试模型，失败再走库**；库动作是候选，不是默认。
**交付必须标来源**：`action.json` 的 `source` + `origin`，索引表第 2 列直接可见。

## 1.2 目录约定

```
Arts/                 原始素材（角色、库片段）
  └── mixamo/         按类别分目录放下载的片段
outputs/
  ├── rig/<角色>/     rig_preprocess 产物
  ├── samples/<批次>/  模型采样批次（中间产物，可清理）
  └── actions/<动作>/  ★ 已验收动作（交付物），每个含 action.json
```

## 2. 决策流程（按顺序问四个问题）

| # | 问题 | 工具 | 走哪条 |
|---|---|---|---|
| 1 | 这个动作在训练分布里吗？ | `caption_stats.py --grep <词>` | 占比 ≥1% → 产线 A |
| 2 | 动作库里有吗？ | Mixamo / Truebones / 自录 | 有 → 产线 B |
| 3 | 机械上能补吗？ | `add_root_spin` / `flatten_root` | 刚体、根位移 → 产线 C |
| 4 | 都没有 | 手工关键帧 / 微调训练 | 见 `docs/动作能力清单.md` |

## 3. 两条产线的命令

### 产线 A：模型生成

`````````bash
# 一条龙：体检 -> 精简 -> 打标签 -> 采样 -> 导出
bash pipelines/unimate/scripts/unimate-pipeline.sh --input <资产> --reps 6

# 循环化（走/跑）+ 打包 Unity
bash pipelines/unimate/scripts/unimate-loop.sh --samples outputs/samples/<资产> --name <资产> \
    --rig outputs/rig/<资产>/<资产>.glb
`````````

### 产线 B：动作库接入

`````````bash
bash pipelines/unimate/scripts/unimate-import-clip.sh \
    --clip "Arts/Sprinting Forward Roll.fbx" \
    --rig outputs/rig/X_Bot --name X_Bot \
    --out outputs/samples/act_roll_fwd \
    --expect roll --action act_roll_fwd
`````````

`--expect` 是质量闸门：`motion` 只要求四肢在动（默认），`roll` 要求整圈翻转。
不通过会打印原因并以非零码退出。

## 4. 输出契约：每个动作目录必须有 action.json

> 字段允许值与必填项的唯一出处是 `core/action_schema.py`（`SOURCES` / `LOOP_MODES` /
> `REQUIRED_FIELDS` / `validate()`）。加来源（例如动补的 `capture`）只改那一处，
> `action_meta.py` 与 `action_index.py` 会自动跟上。

两条产线都写同一个格式，下游只认这一份。

`````````json
{
  "kind": "action",
  "version": "1.0.1.0",
  "name": "act_roll_fwd",
  "source": "library",          // model | library | hybrid
  "origin": "Sprinting Forward Roll.fbx",   // 库片段名 或 prompt
  "rig": "X_Bot",
  "frames": 36,
  "fps": 30,
  "loopable": false,
  "in_place": true,
  "files": ["X_Bot-Sprinting_Forward_Roll.fbx", "..."],
  "qa": { "ok": true, "note": "真翻滚（转角 484°、四肢 50%）" },
  "created": "2026-11-03"
}
`````````

为什么必须有：

- **可追溯**：`source` + `origin` 记住这段动作是生成的还是库里的，库动作涉及授权；
- **可筛选**：`loopable` / `in_place` 决定它在状态机里挂哪个节点、根位移由谁负责；
- **可回归**：`qa` 记录当时通过的检查，换机器重跑能对比。

## 5. 命名规范

| 前缀 | 含义 | 例 |
|---|---|---|
| `gen_*` | 模型生成 | `gen_walk_fwd`、`gen_idle_a` |
| `lib_*` | 动作库片段直接接入 | `lib_dive_roll` |
| `act_*` | 关键动作（多为库，带业务语义） | `act_roll_fwd`、`act_hit_knockdown` |
| `loc_*` | 位移循环（走/跑/爬行） | `loc_walk`、`loc_run` |

规则：全小写、下划线分词、不带角色名（角色写在 `rig` 字段里）。

## 6. 质量闸门（三道）

| 闸门 | 何时 | 工具 | 不通过怎么办 |
|---|---|---|---|
| 体检 | 接资产前 | `unimate-inspect.sh` | 精简骨架 / 修绑定 |
| 动作有效性 | 生成或接入后 | `verify_anim.py --expect motion` | 多采几次 / 换 prompt / 换片段 |
| 循环接缝 | 循环动作 | `make_loop.py` 的 `loop_report.json`（接缝 ≤1.5 为好） | 换一条 / 用 `--close` |

多足再加一道：`gait_report.py`（判断步态相位是否成型）。

## 7. Unity 侧约定

| 字段 | 在 Unity 里怎么用 |
|---|---|
| `loopable: true` | Loop Time 打勾，挂进循环状态（idle/walk/run） |
| `loopable: false` | 一次性动作，用 Trigger 过渡，过渡时间 0.1~0.15 秒 |
| `in_place: true` | 位移由 CharacterController 负责 |
| `in_place: false` | 开 Root Motion，或自己取位移曲线 |
| `fps: 30` | 与所有动作一致，避免混合树错位 |

所有动作共用角色本体建的 **同一个 Avatar**（Humanoid + Copy From Other Avatar），
否则动作之间无法过渡。

## 8. 现状与缺口

| 项 | 状态 |
|---|---|
| 产线 A（模型） | 已通：采样 → 循环化 → 打包 Unity |
| 产线 B（动作库） | 已通：精简 → 特征 → 关节对齐 → 驱动 → 质量闸门 |
| 产线 C（混合） | 仅限刚体；有四肢的动作别用 |
| 统一 action.json | **两条产线都已写入** |
| 动作注册表（跨目录索引） | 未做：目前靠各目录的 action.json，需要时再汇总 |
| 状态机自动生成 | 未做：Unity 侧手工建，字段已够用 |

## 9. 许可提醒

`source: library` 的动作来自第三方动作库（Mixamo / Truebones 等），
授权跟着原始库走；`source: model` 的是生成结果，但权重本身是 CC BY-NC 4.0（不可商用）。
两条都要在 `origin` 里留痕，别到用的时候才想查。
