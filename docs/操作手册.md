# 操作手册（照着做就行）

> 每个场景从"要什么"开始，到"怎么验收"结束。命令都在工程根目录下执行。
> 决策依据见 `docs/动作能力清单.md`，命名与契约见 `docs/动作产线规范.md`。

## 0. 动作来源的优先级（先说清楚）

| 顺序 | 来源 | 什么时候用 | 标记 |
|---|---|---|---|
| **1** | **模型生成** | 训练分布内的动作（走/跑/待机/跳/舞蹈/动物运动…） | `source: model` |
| **2** | **动作库** | 模型做不出、或做不好（翻滚/受击/攀爬/武器/手势） | `source: library` |
| 3 | 程序补 | 刚体、根位移这类机械修正 | `source: hybrid` |

**优先用生成的动作**：它能出随机变体，换个 prompt 就是另一条；
库动作是固定片段，同一段用在所有角色上会看出重复。

**交付时必须能看出用的是哪个来源**——写在 `action.json` 的 `source` / `origin` 里，
索引表第 2 列直接显示。别人拿到动作不用问就知道来源。

## 场景 A：新角色 → 一整套通用动作（走 / 跑 / 待机）

**前置**：资产已经绑定好（一个 armature + 蒙皮）。

`````````bash
# 1) 体检：关节数、是否绑定、有没有空权重顶点
bash pipelines/unimate/scripts/unimate-inspect.sh --input "Arts/新角色.fbx" --no-bones

# 2) 超限就精简（Mixamo 绑定 65 -> 22）
bash pipelines/unimate/scripts/unimate-simplify.sh --input "Arts/新角色.fbx" --mode mixamo

# 3) 一条龙：打标签 -> 采样 -> 导出
bash pipelines/unimate/scripts/unimate-pipeline.sh --input "Arts/新角色.fbx" --reps 6 --exp-dir models/unimate_mixamo_f60_v2

# 4) 循环化 + 打包 Unity（走/跑这类要循环）
bash pipelines/unimate/scripts/unimate-loop.sh --samples outputs/samples/新角色 --name 新角色 \
    --rig outputs/rig/新角色/新角色.glb
`````````

**验收**：
- `outputs/rig/<角色>/summary.json` 里 `fits: true`
- `preview.png` 里角色站直、面朝 +Z
- 循环报告 `loop_report.json`：走/跑接缝 ≤1.5；待机允许"收拢"
- `outputs/actions/gen_.../action.json` 存在，`source: model`

**动物/四足角色多一步**：跑完用 `gait_report.py` 看相位。四条腿同相（+0.9 以上）= 整体弹跳、
不是步态，这条别进状态机（见 AGENTS.md 5.5.1）。

**失败处理**：`fits=false` → 先精简；动作抖动 → 提高 `--cfg_scale` 或多采；
循环接缝大 → 多采几条挑最好的，或待机类用 `--close`。

## 场景 B：补一个模型做不出的关键动作（单条，从库）

**前置**：从 Mixamo 下好片段（`Skin: Without Skin`，30fps），放到 `Arts/mixamo/<类别>/`。

`````````bash
bash pipelines/unimate/scripts/unimate-import-clip.sh \
    --clip "Arts/mixamo/rolls/Dive Roll.fbx" \
    --rig outputs/rig/X_Bot --name X_Bot \
    --expect roll --action act_dive_roll
`````````

参数怎么给：

| 参数 | 取值 | 说明 |
|---|---|---|
| `--expect` | `roll` / `motion` | 翻滚类必须 `roll`，其余 `motion` |
| `--action` | `act_<含义>` | 关键动作用 `act_`，普通库片段用 `lib_` |
| `--out` | 默认 `outputs/actions/<动作名>` | 一般不用给 |
| `--loopable` | 要循环才加 | 写进 `action.json` |

**验收**：
- 屏幕最后一行 `判定: 通过 — ...`
- `outputs/actions/act_dive_roll/action.json` 里 `source: library`、`qa.ok: true`
- 不通过时看 `qa.json` 的 `note`：`四肢几乎不动` 说明片段有问题或接错了骨架

## 场景 C：一次补一批库动作

`````````bash
bash pipelines/unimate/scripts/unimate-import-batch.sh \
    --clips Arts/mixamo/hits \
    --rig outputs/rig/X_Bot --name X_Bot \
    --prefix act_
`````````

- `--expect auto`（默认）：名字里带 roll/flip/cartwheel 的自动按 `roll` 验，其余按 `motion`
- 最后一行 `成功 N 个，失败 M 个`；有失败会列清单并以非零码退出
- 每个片段的详细日志在 `tmp/import_batch_<片段名>.log`

**验收**：`python core/action_index.py`，表里新动作都是 `library` 且质检通过。

## 场景 D：盘点 / 更新索引

`````````bash
python core/action_index.py
# -> outputs/actions_index.md / .json
`````````

索引会报三类问题：**重名**（同 source+name 出现在两个目录）、**文件缺失**、**质检不通过**。
每次新增动作后重跑一次，它同时是"当前资产清单"。

## 场景 E：判断一个动作该不该走库

`````````bash
python pipelines/unimate/tools/caption_stats.py --meta tmp/meta --grep "crawl"
`````````

- 占比 ≥1% → 先试模型（`--reps 6`）
- <1% 或查不到 → 直接走库
- 表见 `docs/待补动作清单.md`


## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `joint order is not the motion's` | 片段和角色骨架顺序不同 | 用 `unimate-import-clip.sh`（它内部会 remap），别手搓 |
| `no such directory or cond file` | 路径相对 UniMate 仓库解析了 | 传绝对路径，或用 `scripts/` 下的封装（内部会转绝对） |
| `blender: command not found` | 没装 shim | `bash pipelines/unimate/scripts/install_blender_shim.sh` |
| 闸门报"四肢几乎不动" | 片段本身没动作 / 接错骨架 | 换片段；或确认 `--rig` 指对了角色 |
| 重复运行产生 `_v2` 文件 | 默认不覆盖 | 加 `--force`，或直接重跑封装（内部已处理） |
